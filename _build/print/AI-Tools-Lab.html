The rule for this lab

You can complete every Level 1 lab for free. Most Level 2 labs are free too. Paid tools appear only where real messages, phone calls, or production hosting are involved, and each class says so clearly.

13.5 What you need before you start

Hardware and software: any laptop from the last five years works. For Claude Code you also need a terminal (built into macOS and Windows) and, for some installs, Node.js from nodejs.org. Nothing in this lab needs a powerful computer, because the AI runs in the cloud.

13.6 Accounts, API keys and safety

Many labs connect one app to another. There are three ways apps connect, and you will meet all three:

Five safety rules for every lab

  1. Never paste an API key into a chat, a document, a prompt, or frontend code. Keep keys in the tool's secret store (n8n credentials, Lovable or Replit secrets, Netlify environment variables).
  2. Use test data. Do not upload customer data, salary data or anything under NDA to a free AI plan. Check your company's AI policy first.
  3. Approve actions one by one until a workflow has run correctly at least ten times.
  4. Turn off what you no longer use. Disconnect connectors and delete unused API keys.
  5. Set spending limits on every paid API (Anthropic Console, OpenAI, Twilio, Vapi) before your first test.

13.9 Exercises with model answers

Exercise 1 · Pick the tools

A D2C brand wants: a landing page with a waitlist form, an email to each signup, and a weekly Slack summary of signups. Which tools would you use, free first?

Model answer

Landing page and form: Lovable (free tier) or Claude artifacts for a quick static page. Email and Slack: Zapier (free covers a two-step "new form row → send email" Zap) plus a second Zap for the weekly summary, or one n8n workflow that does both. Summary text: an AI step (Claude via n8n, or Zapier's AI step). Paid only when signups exceed the free task limits.

Exercise 2 · Spot the risk

A teammate pasted the company's OpenAI API key into a Lovable prompt so the app "can talk to AI". What is wrong, and what should they do?

Model answer

The key is now in the chat history and may end up in frontend code where any visitor can read it. Revoke the key immediately, create a new one, and store it as a secret (Lovable Cloud or Supabase secrets) used only by a server-side function. Set a spending limit on the new key.

13.10 Key takeaways

  • Choose the tool group by the job, and the tool by cost, integrations and team fit.
  • Every Level 1 lab is free. Messages, calls and production hosting are what cost money.
  • Keep secrets out of prompts and frontend code, use test data, and set spending limits.
  • Connectors, API keys and MCP are the three ways tools talk to each other.

Check your understanding

Which group would you use to change code inside an existing GitHub repository?

  1. AI assistants such as the Claude chat app
  2. Coding agents such as Claude Code
  3. Automation tools such as Zapier
  4. Voice agents
Why: Coding agents read, edit and commit code in a real repository.

What usually costs money even when you are only testing a WhatsApp or phone bot with real people?

  1. Writing the prompt
  2. Designing the flow in Figma
  3. Delivered messages and call minutes
  4. Creating a Google account
Why: Messaging and telephony are billed per message or per minute.

Where should an API key for an automation live?

  1. In the prompt so the AI can see it
  2. In a shared Google Doc
  3. In the tool's credential or secret store
  4. In the website's JavaScript
Why: Credential stores keep keys encrypted and out of chats and frontend code.

Claude for Daily PM Work: Basic to Advanced

Use Claude every day for writing, research, analysis and prototypes, then connect it to Gmail, Calendar, Drive, Slack, GitHub and your own tools.

14.1 What Claude is and where you can use it

Claude is Anthropic's AI assistant. You talk to it in plain language, give it files, and it writes, analyses, researches, codes and builds small apps. The same account works in several places:

14.1.1 Plans

Plan Who it is for What you get (checked 23 Oct 2026)

Pro Individual PMs More usage, Projects, more models, Claude Code included
Max Heavy daily users 5× or 20× Pro usage, priority access, early features

14.2 Level 1 · Your first hour with Claude

Level 1 · Beginner

Goal: get one genuinely useful result (a meeting summary, an email, a first PRD draft) and learn the four habits that make answers better.

14.2.1 The anatomy of a good prompt

Most weak answers come from missing context, not from a weak model. Use four parts:

14.2.2 Four habits for Level 1

  1. Give the source material. Attach the PDF, CSV or notes instead of asking from memory.
  2. Ask for a format. Tables, bullet lists, "max 150 words", "for a VP audience".
  3. Iterate in the same chat. "Shorter", "more specific", "add a risks section".
  4. Start a new chat for a new topic. Long mixed chats get slower and less focused.

14.2.3 Files Claude can read

PDFs, Word documents, slides, spreadsheets and CSVs, images and screenshots, and plain text or code files. Claude can run code to analyse data files: upload a CSV and ask for averages, a chart or a cohort table.

Data analysis prompt

"Here is orders.csv. 1) Describe the columns. 2) Weekly order count and average order value. 3) A line chart of both. 4) Three observations a PM should act on. Show the method, so I can check it."

14.3 Level 2 · Features working PMs use every week

Level 2 · Working PM

Goal: stop re-explaining your product in every chat, produce documents and prototypes you can share, and research with sources.

14.3.1 Projects: your product's memory

A Project is a workspace with custom instructions and knowledge files that every chat inside it can use. Make one Project per product or per big initiative.

14.3.2 Artifacts: documents, code and clickable prototypes

When Claude produces something substantial (a document, a diagram, a web page, a small app), it appears as an artifact in a panel beside the chat. You can edit it by asking for changes, see versions, copy or download it, and publish it to get a link you can share.

14.3.3 Research with sources

Turn on web search (and Research, where your plan offers it) for questions that need current information: competitors, regulations, market sizes. Research runs many searches and returns a report with citations.

Always open the sources

Click at least three citations and confirm the claim is really there. AI research can misread a source or rely on a weak one. Mark any number you could not verify as "unverified" in your document.

14.3.4 Styles, memory and skills

  • Styles set how Claude writes (concise, formal, explanatory, or a custom style learned from your own writing samples).
  • Memory and past-chat search (where enabled) let Claude recall earlier work. You can view, edit or turn memory off in Settings.
  • Skills are packaged instructions (and sometimes scripts) that teach Claude a repeatable task, such as your company's PRD format or a spreadsheet report. Claude loads a skill when the task matches. You can use Anthropic's skills and create your own.

14.4 Level 3 · Connect Claude to your apps

Level 3 · Advanced

Goal: let Claude read your email, calendar, documents and Slack, act with your approval, and use your own tools through MCP.

14.4.1 Connectors

Connectors give Claude permission to use another app on your behalf. Go to Settings → Connectors, click Connect next to a service, sign in, and approve the permissions.

14.4.2 What PMs do with connectors

Connector Daily use Example prompt
Gmail Triage, find decisions, draft replies "Find every email about the payments launch this month. List decisions and open questions, then draft a reply to the latest thread."
Google Calendar Prep and planning "What meetings do I have tomorrow? For each, what should I prepare, based on related Drive docs?"
Google Drive Search and summarise docs "Compare the Q3 and Q4 roadmap docs and list what moved."
Slack Catch up and draft updates "Summarise #checkout-squad since Monday: decisions, blockers, who is waiting on me."
GitHub Read code and issues "Read the open issues labelled 'checkout' and group them by theme."
Notion / Figma Specs and designs "Pull the requirements from the Split Bill PRD in Notion and check the Figma file covers each one."

14.4.3 Custom connectors and MCP

MCP (Model Context Protocol) is an open standard that lets an AI assistant use tools from another system. A remote MCP server has a URL. Add it under Settings → Connectors → Add custom connector, and Claude gets that server's tools. In Class 20 you will build an n8n workflow with an MCP Server Trigger and add it to Claude, so you can say "log this bug to our tracker" and n8n does it.

14.4.4 The API and Claude Console

To put Claude inside your own app, bot or automation, you use the Claude API:

  1. Sign in at console.anthropic.com (separate billing from your claude.ai plan).
  2. Add a payment method and set a monthly spend limit.
  3. Create an API key and store it in a secret store (never in a chat or frontend code).
  4. Test prompts in the Workbench, then use the key in n8n, Make, Zapier, Lovable or code.

14.5 A daily routine for PMs

14.6 Labs

Lab 1 · Build your product Project (20 minutes)

  1. Projects → New project → name it after your product.
  2. Write instructions: product in one line, users, goals this quarter, writing rules, "flag assumptions".
  3. Upload three files: a strategy or vision doc, personas, and one metrics CSV (use datasets/orders.csv from this handbook if you have nothing).
  4. Ask: "Using only the knowledge files, what are the three biggest risks to this quarter's goal?"
  5. Check the answer cites the files. If it invents facts, add to the instructions: "Answer only from the knowledge files; say 'not in files' otherwise."

Lab 2 · Interview synthesis (30 minutes)

  1. Inside your Project, attach five interview notes (real or written by you).
  2. Prompt: "Affinity-map these interviews: themes, number of users per theme, one quote each, and the job-to-be-done behind each theme."
  3. Follow up: "Which theme is most likely to change our roadmap? What would we need to believe?"
  4. Save the result as an artifact document and publish it for your team.

Lab 3 · A clickable prototype you can share (30 minutes)

  1. Prompt: "Build a mobile-first clickable prototype for [feature]: three screens, sample data only, a 'Prototype · not real' label."
  2. Ask for two changes, one at a time.
  3. Ask for an edge case: "Add the empty state and an error state."
  4. Click Publish, open the link in a private window, and check it works on your phone.

Lab 4 · Morning brief from Gmail and Calendar (15 minutes)

  1. Settings → Connectors → connect Gmail and Google Calendar (use a practice account first).
  2. In a new chat, turn both on in the tools menu.
  3. Prompt: "Brief me for today: meetings with what to prep, emails that need a reply from me, and anything with a deadline this week."
  4. Ask Claude to draft two replies. Open Gmail and check the drafts are there. Claude drafts; you review and send.

Lab 5 · Weekly Slack update (15 minutes)

  1. Connect Slack (practice workspace).
  2. Prompt: "Read #practice-squad from the last 7 days. Draft a weekly update: shipped, in progress, blocked, decisions needed. 120 words."
  3. Edit the draft yourself before posting. You own what you send.

Lab 6 · Give Claude a custom tool (advanced, after Class 20)

  1. Build the n8n "log a bug to Google Sheets" workflow with an MCP Server Trigger (Class 20, Lab 5).
  2. Copy its production URL.
  3. Claude → Settings → Connectors → Add custom connector → paste the URL.
  4. In a chat: "Log a bug: checkout button overlaps on small screens, high priority." Approve the tool call, then check the sheet.

14.8 Common mistakes

  • No context: asking "write a PRD" with no product, users or goal. Use a Project.
  • Trusting numbers and quotes without checking: always verify against the source.
  • Pasting confidential data into a personal plan: follow your company's AI policy; use Team or Enterprise for work data.
  • One endless chat: start a new chat per task; keep long-lived context in the Project.
  • Letting Claude send on your behalf too early: keep approvals on for email and Slack actions.

14.11 Key takeaways

15.1 What Claude Code is

Claude Code is an agentic coding tool. You describe what you want in plain language; it reads the files in a project, plans, edits code, runs commands (tests, builds, git), shows you what it changed, and asks permission before risky steps. Module 11 introduced it for vibe coding. This class goes from first install to advanced automation.

Why a PM should learn it

You can build and change prototypes yourself, answer "how does this feature actually work?" by reading the codebase, write data scripts, fix copy and small UI bugs, update documentation, and turn a PRD into a working demo in an afternoon. Engineers still review anything that goes to production.

15.3 Creating a repository and pushing to GitHub

Every project you build should live in a git repository, so you can undo mistakes and share the work.

Prompt that does it all

15.5 Level 3 · Extending Claude Code

Level 3 · Advanced

Goal: give Claude new tools (MCP), reusable know-how (skills and commands), helpers (subagents), automatic checks (hooks), and run it without you (headless, GitHub, web).

15.5.1 MCP servers: new tools for Claude

Add an MCP server once, and Claude can use its tools in every session. Use claude mcp add, or /mcp inside a session.

15.5.2 Skills and custom commands

  • A skill is a folder with a SKILL.md file (instructions, examples, optional scripts) inside .claude/skills/ in your project or your user folder. Claude uses it automatically when a task matches its description. Example: a "release-notes" skill that turns merged pull requests into customer-friendly notes in your house style.
  • A custom slash command is a Markdown prompt in .claude/commands/, run by typing /its-name. Example: /prd-check asks Claude to compare the code with docs/prd.md.

15.5.3 Subagents

A subagent is a helper with its own instructions, tools and separate context. Create one with /agents. Good PM examples: a reviewer that checks a change against the PRD, a tester that runs Playwright checks, a copy editor that enforces your tone guide. Subagents keep long, noisy work out of your main conversation.

15.5.4 Hooks

Hooks run your own script automatically at set moments, for example before a tool runs (block edits to .env), or after a file is edited (run the formatter). Manage them with /hooks. Hooks are rules that always run, unlike instructions, which Claude may occasionally miss.

15.5.5 Plugins

A plugin bundles skills, subagents, commands, hooks and MCP servers so a team can install the same setup with one /plugin command. Use them to share your team's standard Claude Code setup.

22.1 What a voice agent does

A voice agent is an AI that talks on the phone (or in a browser or app). It listens, understands, answers, and can take actions such as booking an appointment, then hands the call to a person when needed.

22.2 How a call works

22.3 Platforms

Phone numbers in India. Providers such as Exotel, Plivo and Knowlarity offer Indian virtual numbers and connect to voice platforms (often via SIP). Indian numbers require KYC documents. International platforms may offer Indian numbers only through a partner, so check availability before choosing a platform.

Indian languages. Check each platform's supported languages and test Hindi and regional-language calls with real speakers. Accents, code-mixing (Hinglish) and background noise affect accuracy.

22.3.1 What it costs: a worked example

A clinic receives 1,000 calls a month, averaging 3 minutes. 22.4 The law and consent (summary, not legal advice)

Before any real call

  • Tell callers it's an AI at the start, and say if the call is recorded.
  • Outbound calls need prior consent. In India, commercial calls fall under TRAI's commercial communication rules (registration, DND preferences, consent). In the US, the FCC treats AI-generated voices in robocalls as "artificial" under the TCPA, so prior express consent is required.
  • Personal data: collect the minimum, store recordings securely and delete them on schedule (India's DPDP Act, GDPR in Europe).
  • Offer a human option ("press 0 or say 'agent'") and honour do-not-call requests.

22.5 Designing the conversation

Voice prompt rules

  • Replies under two sentences; no lists, tables or URLs (they don't work in speech).
  • Say numbers the way people speak them ("four-thirty in the afternoon").
  • Handle silence ("Are you still there?") and interruptions gracefully.
  • Give a clear way out: "If you'd like to talk to someone, just say 'staff'."
  • Never guess. "I'm not sure, let me get a colleague to call you back."

A car service centre gets 600 calls a month, 4 minutes each. Platform quotes $0.12 a minute all-in. Staff handle 20% of calls after transfer. Monthly AI cost?

600 × 4 × $0.12 = $288 a month for agent minutes (assuming the transfer happens after most of the call; transferred minutes may continue to be billed until the agent leaves the call). Add the number rental and platform plan, and staff time for the 120 transferred calls.

Exercise · Fix the script

The agent says: "Our services include haircut ₹500, colour ₹2,500, spa ₹1,800, visit glowsalon.com/book or press 1 for…" What's wrong?

Model answer

Too long, a list and a URL in speech. Better: "We do haircuts, colour and spa treatments. Which one are you interested in?" Then give the one price asked for, and offer to book or send a WhatsApp link.

22.10 Key takeaways

  • A voice agent = phone + speech-to-text + AI model + text-to-speech + tools + handoff.
  • Choose Retell AI or ElevenLabs for speed, Vapi or Twilio for control, a no-code builder for non-technical teams.
  • Budget all-in per-minute cost, not the headline platform fee.
  • Disclose AI, get consent for outbound calls, and follow local telecom and privacy rules.
  • Read back details, keep replies short, and test with real speakers before going live.
